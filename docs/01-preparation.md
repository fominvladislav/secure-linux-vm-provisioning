# Подготовка к развертыванию Linux VM

Необходимо собрать все обязательные параметры, исключив отсутствующие или противоречивые данные.

## Input data

| Параметр | Пример |
|---|---|
| Назначение | application server |
| Владелец | команда приложения |
| Среда | development / test / production |
| Имя VM | `linux-vm-01` |
| FQDN | `linux-vm-01.corp.example.com` |
| ОС | поддерживаемая Ubuntu LTS или RHEL-совместимая ОС |
| Ресурсы | `4 vCPU`, `8 GiB RAM` |
| Диски | system, data, logs |
| Сеть | IP, prefix, gateway, DNS, VLAN/port group |
| Доступ | административные группы и сервисные учетные записи |
| Домен | нужен или не нужен |
| Backup | RPO, RTO и перечень данных |
| Monitoring | шаблон, теги и ответственные |
| Maintenance | окно обслуживания |

## Responsible roles

| Роль | Ответственность |
|---|---|
| User | Описывает назначение и требования |
| Владелец сервиса | Подтверждает параметры и принимает сервер |
| Virtualization | Создает VM |
| Network / IPAM / DNS | Выделяет адреса и создает DNS-записи |
| Linux Operations | Настраивает ОС |
| Identity / AD | Определяет домен, OU и группы |
| Security | Проверяет требования безопасности |
| Monitoring | Подключает наблюдаемость |
| Backup | Подключает резервное копирование |

Вместо имен отдельных сотрудников в инструкции должны использоваться роли, группы или очереди поддержки.

## Checking the request

До начала работ необходимо убедиться, что:

- имя сервера уникально;
- IP-адрес зарезервирован и не занят;
- выбран правильный сетевой сегмент;
- известны A- и PTR-записи;
- ресурсов достаточно;
- определены размеры и назначение дисков;
- указан владелец;
- определено окно обслуживания;
- понятна схема доступа;
- согласована необходимость Active Directory;
- определены backup и monitoring;
- известны команды, выполняющие каждый этап.

## Preparing the network

Нужно получить из IPAM или от сетевой команды:

- IP-адрес;
- prefix;
- gateway;
- DNS-серверы;
- search domain;
- VLAN или port group;
- статические маршруты;
- дополнительный интерфейс, если нужен backup или management;
- требования firewall.

Для каждого интерфейса должны быть указаны его назначение и маршруты.

Несколько default routes нельзя создавать без формального routing design.

## DNS

До или во время развертывания создаются:

- A-запись;
- PTR-запись;
- дополнительные записи, если они действительно нужны.

Пример:

```text
linux-vm-01.corp.example.com -> 192.0.2.20
192.0.2.20 -> linux-vm-01.corp.example.com
```

Проверка:

```bash
getent hosts linux-vm-01.corp.example.com
getent hosts 192.0.2.20
```

## Active Directory

До создания VM следует определить:

- нужен ли ввод в домен;
- домен;
- OU;
- группы доступа;
- способ интеграции: SSSD или Winbind;
- учетную запись с делегированными правами;
- требуется ли заранее создавать объект компьютера.

Предварительное создание объекта в AD - не универсальное техническое требование. Оно зависит от делегирования прав и внутреннего процесса.

## Backup и monitoring

Заранее определить:

- что резервировать;
- как часто;
- срок хранения;
- RPO и RTO;
- кто проверяет backup;
- какой monitoring-agent используется;
- какие шаблоны и теги применяются;
- куда поступают алерты;
- кто является владельцем алертов.

## Security

До начала создания согласовать:

- способ административного доступа;
- SSH-ключи;
- правила sudo;
- firewall;
- SELinux или AppArmor;
- vulnerability scanning;
- security-agent;
- журналирование;
- patch management.

Не использовать как стандарт:

- общий пароль `root`;
- общую административную учетную запись;
- `NOPASSWD: ALL`;
- пароли или токены внутри тикета и Git-репозитория.

## Stage result

Подготовка завершена, когда:

- обязательные параметры заполнены;
- роли и владельцы определены;
- сеть согласована;
- IP зарезервирован;
- DNS подготовлен;
- backup и monitoring определены;
- требования к домену понятны;
- есть план отката;
- создание VM разрешено.
